# L.6.4c — коррекция отказа до применения

## Изменения

Ранее Team могла использовать слот `repair` после функционального провала и отката. Теперь инструментальный автономный сеанс сортировки может использовать тот же слот при точно диагностированном превышении размера `app.py`. Лимиты остались 4096 символов на файл и 4400 байт UTF-8. Схема доступа, 11 сценариев, дедлайны, число облачных запросов и бюджет правок сохранены.

До классификации проверяются схема ответа, путь, SHA-256 исходника, уникальность и непересечение замен, допустимость текста, синтаксис Python и наличие точки входа. Core сохраняет оригинальный ответ и точный восстановленный кандидат. Для производного Approval Core заново проверяет результат по запечатанному ответу и совпадение области. Engineer получает исходную задачу, требования, полный ранее предложенный `app.py`, его SHA-256, причину отказа, фактические размеры и допустимые пределы. Точечные замены коррекции явно привязаны к этому кандидату.

Допустимый результат коррекции применяется существующим Executor относительно исходного снимка. Способ записи и штатная проверка Docker Worker сохранены. При функциональном провале после такой коррекции выполняется откат и сеанс останавливается. Оба пути используют один слот `repair`. При отказе по другим причинам, повреждении доказательств, `unknown` или выходе из области новая коррекция блокируется. Чрезмерный кандидат, который не помещается в действующий контекст, тоже останавливает цепочку. Код официального DevKit не менялся.

## Историческое испытание

Артефакты L.6.4b сверены. Engineer завершил генерацию за 75,922 с, четыре замены собрали 4102 символа и 4102 байта, превысив предел символов на шесть. Новый валидатор повторно классифицировал сохранённый ответ только для диагностики. Полный кандидат и диагностика помещаются в запрос коррекции (6368 байт UTF-8 во всём тексте запроса). Исторический Run и его Approval не изменены.

Штатное продолжение из завершённого сеанса с переносом результатов поддерживается для проекта фильтрации. Для завершённого сеанса сортировки такой путь отсутствует. Поэтому реальное испытание проводится отдельным полным автономным сеансом с одним новым согласованием. Работа исходного сеанса не переисполняется.

## Проверки реализации

Шесть целевых сценариев прошли. Они покрывают превышение символов и байтов, точную диагностику и оригинальный кандидат, одну коррекцию, исчерпание её после функционального отказа с откатом, остановку при unknown и запрет правки постороннего файла. Прежний маршрут подтверждён полной Python-регрессией: 1046 успешных тестов, один пропуск из-за локальной экзаменационной фикстуры. Все 37 тестов DevKit прошли. Ruff с правилами E4, E7, E9 и F и проверка пробельных ошибок Git прошли.
