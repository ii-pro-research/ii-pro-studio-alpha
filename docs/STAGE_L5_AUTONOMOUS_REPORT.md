# L.5 — автономный инженерный сеанс Balanced

Studio может провести Architect → Local → Engineer → Engineering Executor → Worker → Architect после одного согласования. Ручной режим остался доступен. В v0.1 автономность ограничена зарегистрированными WSGI-стендами task-manager и task-manager-filter, одним разрешённым app.py и закреплённой приёмкой. Изменения остаются в запечатанной логической копии Core.

## Область и исполнение

Оператор видит цель, критерии, снимок, файлы, инструменты, модели, версии и профили исполнителей, количество облачных и локальных вызовов, лимит исправлений, изолированные проверки, их ресурсные пределы, срок и условия остановки. Согласование связывает SHA-256 области. Core связывает каждый производный Approval с Run, хешем OperationSpec, областью и конкретным слотом. Резервирование слота и запись approval.derived идут одной транзакцией. Событие отличается от ручного approval.decided. Резерв расходуется даже при заблокированном последующем запуске. Автономный Run нельзя одобрить ручным вызовом ApprovalManager в Studio.

Core проверяет производное разрешение повторно перед исполнением. Оно требует неизрасходованного уникального слота, неизменного задания, версии исполнителя, файлов и параметров, действующего согласия и достаточного остатка времени. Срок самого Approval остаётся неизменяемым. Одновременно исполняется один Run. Используются существующие Task, Run, Artifact, Worker и журнал. Новых таблиц и очередей нет.

Пауза, остановка и отзыв блокируют следующие операции. Запрос, уже переданный исполнителю, может завершиться. Это не считается доказательством удалённой остановки. При unknown цепочка останавливается, операция не повторяется. Перезапуск процесса сам по себе не запускает операцию. Восстановление допускается только с действующим неизменным разрешением и текущим Approval.

## Ошибки и итоговый разбор

При подтверждённом провале тестов система извлекает сценарии и коды ошибок из запечатанной квитанции. Детерминированная диагностика помечает вероятную область проблемы и передаёт Engineer краткое свидетельство вместе с исходным снимком. Engineering Executor сначала восстанавливает точную резервную копию отдельным производным Approval. При согласованном резерве формирует один исправленный кандидат и повторяет приёмку. При исчерпании резерва второй неудачный кандидат откатывается, сеанс завершается. Если Worker в unknown или срок исчерпан, новые операции не допускаются. Исходный рабочий проект не изменяется.

В итоговый запрос Architect входит фактический исходник принятой копии, помеченный фрагмент diff, SHA-256 и результаты Worker. Размер фрагмента ограничен бюджетом контекста, факт усечения указан. Это позволяет Architect рассмотреть переданную реализацию и отдельно оценить предоставленные результаты. Материал остаётся unreviewed. Новые знания и улучшения Evolution Engine не внедряются сами собой.

## Проверки

Сквозной испытательный сценарий использовал настоящий HTTP API Studio и Mock-исполнителей. Проверены одна пользовательская санкция на маршрут, принятие с первой попытки, провал тестов с откатом и одной правкой, второй провал и исчерпание бюджета, истечение разрешения, пауза, остановка, отзыв, конкурентный запуск, попытка выйти за область и `unknown`. Проверка итогового запроса подтверждает, что Architect получает исходник принятого кандидата и фактические доказательства. Реальное прохождение маршрута остаётся предметом подготовленного сеанса.

Целевой Python-прогон дал 99 успешных тестов. UI дал 93 успешных теста и собрал production-интерфейс. Node.js DevKit дал 33 успешных теста. Ruff прошёл для нового модуля и его тестов.

Полная Python-регрессия дала 964 успешных, 1 пропущенный и 1 сбой. Пропуск относится к локальному экзаменационному артефакту вне Git. Единственный сбой был в тесте дедлайна DevKit. Тест ожидал исключение на уровне Node-моста, хотя мост может штатно отправить терминальное событие `error` с кодом `deadline`. Исправленная проверка подтверждает это событие и отсутствие `completed`. Адаптер по-прежнему преобразует событие дедлайна в неопределённый результат. Затронутый Python-набор DevKit прошёл 15 из 15 после исправления теста. Полный прогон был выполнен один раз и пересчёт его результатов не подменяет отдельный запуск.

Коммит реализации `dc179d2`.
