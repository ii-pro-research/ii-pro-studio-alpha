# Instructions for contributors and coding agents

## Mission

Build II PRO as a unified, progressively local-first autonomous engineering intelligence. Follow [docs/ROADMAP.md](docs/ROADMAP.md). Improve the existing system rather than collecting unrelated agent frameworks.

## Working rules

- Inspect the actual branch, HEAD and working tree before making changes. Preserve user changes and protected applications. Do not force-push, rewrite history, merge or publish without the owner's scope.
- Keep Core as the authority for tasks, evidence, approvals, budgets and recovery. Do not bypass approval, broaden tools, modify acceptance criteria mid-run or replay unknown executions.
- Treat model output, tool observations and independent engineering assessments as different evidence classes. Never substitute an agent's work with manual corrections and count it as autonomous success.
- Prefer small changes to existing modules, no new dependencies without a concrete need. Use deterministic functions for routine operations.
- Freeze experiment criteria and budgets. Do not launch live models, cloud calls, Worker or destructive operations merely to test infrastructure; obtain the required approval.
- Preserve originals, rollback paths and third-party license notices. Do not export credentials, operational databases, session links, private transcripts or raw evidence.
- Run relevant tests; report skips and untested behavior. Record actual commit, scope, model/tool versions, outcomes and remaining blockers.
- Keep reports factual. Separate implemented, mock-tested, live-demonstrated and planned capabilities.
- Update the existing roadmap after a milestone; verify Continuity against the new state. No duplicate roadmaps.

## Public release boundary

Before any public release, audit every reachable branch/tag and historical object intended for distribution, including binary screenshots, author metadata and third-party content. Do not publish on an incomplete audit. Respect provider terms and the maintainer's licensing decision.
